# GOAD Part 4 — Poison and Relay

## Objective

Demonstrate NTLM relay in the GOAD lab by combining:

1. LLMNR/mDNS poisoning with Responder
2. NTLMv2 authentication capture
3. SMB signing assessment
4. NTLM relay with Impacket `ntlmrelayx`
5. SOCKS session registration for successfully relayed SMB authentications

The exercise was performed exclusively against the GOAD lab network:

`192.168.56.0/24`

## Lab Interface

- Interface: `eth1`
- IP address: `192.168.56.133/24`
- GOAD network: `192.168.56.0/24`

Responder was bound specifically to `eth1` so that poisoning traffic remained within the GOAD lab network.

## Relay Surface

The SMB signing baseline identified two responsive hosts with SMB signing disabled:

| Host | IP Address | SMB Signing |
|---|---|---|
| CASTELBLACK | `192.168.56.22` | Disabled |
| BRAAVOS | `192.168.56.23` | Disabled |

These systems became the NTLM relay targets.

## Poisoning and Authentication Capture

Responder successfully poisoned LLMNR and mDNS name-resolution requests generated by GOAD hosts.

Two NTLMv2 SMB authentication events were observed from WINTERFELL:

- `192.168.56.11` — WINTERFELL
- `NORTH\eddard.stark`
- `NORTH\robb.stark`

Credential and hash material is intentionally excluded from this repository.

## NTLM Relay

The authentication generated by `NORTH\robb.stark` from WINTERFELL was successfully relayed to:

- `192.168.56.22` — CASTELBLACK
- `192.168.56.23` — BRAAVOS

Both relay attempts returned successful SMB authentication, and `ntlmrelayx` registered SOCKS sessions for both targets.

## Result

The Part 4 objective was successfully demonstrated:

```text
LLMNR/mDNS poisoning
        ↓
NTLMv2 authentication
        ↓
NTLM relay
        ↓
SMB authentication
        ↓
CASTELBLACK / BRAAVOS
```

This demonstrates that SMB signing being disabled creates a relayable NTLM authentication surface.

The results do **not** by themselves demonstrate:

- Administrator privileges
- Domain Administrator privileges
- Local privilege escalation
- Remote code execution
- Credential dumping
- Persistence

No post-relay exploitation was performed as part of this documented exercise.

## Evidence Handling

Sensitive authentication material, including NTLM hashes and passwords, is intentionally excluded from the documentation.
